# 模组集成

## 集成策略总览

| 模组 | 依赖类型 | 集成方式 | 声明位置 |
|------|---------|---------|---------|
| AE2 (Applied Energistics 2) | **必需** | 直接 API 调用 | `neoforge.mods.toml` |
| ModernUI | **必需**（客户端） | 框架 API | `neoforge.mods.toml` (side=CLIENT) |
| Flux Networks | 可选 | 运行时检查 + 反射 | 代码内检查 |
| Mekanism | 可选 | 通过 Flux 集成间接访问 | 反射 |
| Draconic Evolution | 可选 | Pylon→Core 反射链路 | `neoforge.mods.toml`（brandonscore） |
| BrandonsCore | 可选 | IOPStorage 能力反射 | `neoforge.mods.toml` |
| Just Enough Characters | 可选（客户端） | MethodHandle 反射 | `neoforge.mods.toml` (side=CLIENT) |

### 适配器模式

所有集成代码集中在 `integration/` 包内。新增模组集成应遵循相同模式：

1. 在 `integration/` 包内创建适配器类
2. 提供静态 `isAvailable()` 方法进行运行时可用性检查
3. 所有 API 调用通过适配器方法封装
4. 在 [[03-方块与实体]] 的 `ObserverBlockEntity` 中通过条件分支调用

## AE2 集成

### 依赖声明

```toml
# neoforge.mods.toml
[[dependencies.resourceobserver]]
modId="ae2"
type="required"
versionRange="[19.2.0,)"
```

```gradle
// build.gradle
compileOnly "org.appliedenergistics:appliedenergistics2:19.2.17:api"
localRuntime "org.appliedenergistics:appliedenergistics2:19.2.17"
```

### 集成方式

AE2 集成**直接内嵌在 `ObserverBlockEntity`** 中（硬依赖，无需适配器包装）：

- 通过 `IStorageService` 接口读取网络存储
- 遍历物品和流体通道
- 计算每次采样的 delta（差值）
- 使用 EMA 平滑速率

### 网络类型

| 类型标识 | 绑定目标 | 数据内容 |
|---------|---------|---------|
| `AE2_ITEMS` | 任意 AE2 网络设备 | 物品/流体清单、产量、消耗、存储容量 |

### AE2 API 使用点

| API | 用途 |
|-----|------|
| `IStorageService` | 获取网络存储服务 |
| 物品/流体遍历 | 获取当前库存快照 |
| Cell 容量查询 | 获取存储单元字节/类型/单位信息 |

## Flux Networks 集成

### FluxNetworksIntegration

**类路径：** `integration.FluxNetworksIntegration`

运行时可选的能量网络适配器。

### 可用性检查

```java
// 运行时检查 Flux Networks 是否加载
FluxNetworksIntegration.isAvailable()
```

在 [[04-物品系统]] 的 `BindingToolItem` 中，通过方块命名空间 + 路径包含 `"controller"` 判断是否为 Flux 控制器。

### 核心方法

| 方法 | 说明 |
|------|------|
| `canProbeFluxNetwork(ServerLevel, BlockPos)` | 检查方块是否为 Flux 控制器 |
| `probeFluxNetwork(ServerLevel, BlockPos)` | 读取完整网络状态 |

### 探测输出：FluxSampleResult

```java
record FluxSampleResult(
    long inputRate,          // 输入速率 (FE/t)
    long outputRate,         // 输出速率 (FE/t)
    long energyStored,       // 当前存储量
    long totalCapacity,      // 总容量
    int plugCount,           // 插头数
    int pointCount,          // 连接点数
    int storageCount,        // 存储设备数
    int controllerCount,     // 控制器数
    List<ExternalGroup> externalGroups  // 外部分组明细
)
```

### 实现细节

- 通过**反射**访问 Flux Networks 内部类
- 读取控制器对象的字段获取网络统计
- 枚举连接设备并按类型分组
- 生成外部分组映射（sub-ID mapping）

### 网络类型

| 类型标识 | 绑定目标 | 数据内容 |
|---------|---------|---------|
| `FLUX_ENERGY` | Flux Networks 控制器 | 输入/输出速率、存储、容量、设备列表 |

## Mekanism 集成

### 集成方式

Mekanism 不是直接集成，而是作为 Flux Networks 集成的**辅助功能**：

- 通过反射访问 `IStrictEnergyHandler` 接口
- 用于 Mekanism 能量单位（Joule）与 FE 的转换
- 仅在 Flux Networks 可用时激活

### 依赖声明

```gradle
// build.gradle
compileOnly "mekanism:Mekanism:${mekanism_version}:api"
localRuntime "mekanism:Mekanism:${mekanism_version}"
localRuntime "mekanism:Mekanism:${mekanism_version}:generators"
```

## Draconic Evolution 集成

### 集成方式

Draconic Evolution（DE）的 Energy Core 作为外部能量容器集成到 Flux Networks 能量页的**外储识别系统**中。全部通过反射访问，无编译期依赖。

### 依赖声明

```toml
# neoforge.mods.toml
[[dependencies.resourceobserver]]
modId="brandonscore"
type="optional"
versionRange="[1.21.1-3.2.0,)"
```

```gradle
// build.gradle（仅 localRuntime）
localRuntime "curse.maven:codechicken-lib-1-8-242818:7281427"
localRuntime "curse.maven:brandons-core-231382:6769922"
localRuntime "curse.maven:draconic-evolution-223565:6770008"
```

### 多方块架构

DE Energy Core 是一个特殊的多方块储能结构：

| 组件 | 类名 | 作用 |
|------|------|------|
| Energy Core | `TileEnergyCore` | 中心方块，存储能量（OPStorageOP） |
| Energy Pylon | `TileEnergyPylon` | I/O 设备，通过 `coreOffset` 连接到 Core |
| Stabilizer | `TileEnergyCoreStabilizer` | 结构验证用，不暴露能量能力 |

Core 激活后被 Structure Block 包围（物理不可访问），必须通过 Pylon 间接交互。

### 探测链路

```
Flux Plug/Point (adjacent) → TileEnergyPylon
    → Pylon.coreOffset.get() → BlockPos offset
    → pylonPos.subtract(coreOffset) → Core 坐标
    → TileEnergyCore.energy (OPStorageOP)
    → getOPStored() / getMaxOPStored() (long 精度)
```

### 分组去重

- 同一 Core 的多个 Pylon 通过 `Core.linkUUID`（ManagedUUID）生成相同 extId：`decore_<uuid>`
- Core 未激活（无 linkUUID）时降级为坐标分组：`decore_<x>_<y>_<z>`
- 客户端 `buildExternalGroups()` 按 extId 合并，`isBidirectionalStorage()` 自动识别双向储能

### 精度说明

| 接口 | 精度 | 最大值 |
|------|------|--------|
| IEnergyStorage（标准 FE） | int | ~2.14B |
| IOPStorage（BrandonsCore） | long | ~9.2E18 |
| OPStorageOP（tier 8 无限） | BigInteger overflow | Long.MAX_VALUE/2 返回值 |

本集成直接读取 Core.energy，绕过 Pylon 的 opAdapter（其 `getEnergyStored()` 会 `Math.min` 到 int 范围），获得 long 精度的真实容量。

### BrandonsCore 通用回退

对于非 DE Pylon 但使用 BrandonsCore OP 系统的方块，通过 `CapabilityOP.BLOCK` 能力进行通用探测（`getOPStored`/`getMaxOPStored`），优先级低于 DE Pylon→Core 直连探测。

## ModernUI 集成

### 依赖声明

```toml
# neoforge.mods.toml
[[dependencies.resourceobserver]]
modId="modernui"
type="required"
side="CLIENT"
versionRange="[1.21.1-3.12.0.2,)"
```

```gradle
// build.gradle
implementation "icyllis.modernui:ModernUI-NeoForge:${modernui_mc_version}"
additionalRuntimeClasspath(compileOnly("icyllis.modernui:ModernUI-Core:${modernui_core_version}"))
additionalRuntimeClasspath(compileOnly("icyllis.modernui:ModernUI-Markflow:${modernui_core_version}"))
```

### 框架使用

ModernUI 提供了 Android 风格的 UI 框架，本项目使用的核心 API：

| 类别 | API |
|------|-----|
| 视图 | `View`, `TextView`, `Button`, `ScrollView`, `LinearLayout`, `FrameLayout` |
| 片段 | `Fragment` 生命周期管理 |
| 图形 | `Canvas`, `Paint`, `ShapeDrawable`, `StateListDrawable` |
| 动画 | `ObjectAnimator`, `AnimatorSet` |
| 度量 | `view.dp()` 密度无关像素转换 |

### 关键差异（与 Android）

- **纯代码布局**（无 XML）
- 右键上下文菜单**不可用**
- 使用 `icyllis.modernui.core.Context` 而非 `android.content.Context`
- 布局参数使用 `MATCH_PARENT(-1)` / `WRAP_CONTENT(-2)` 常量

详见 → [[06-UI系统]] 中 ModernUI 实现部分

## Just Enough Characters (JEC) 集成

### JecIntegration

**类路径：** `integration.JecIntegration`

客户端可选的拼音搜索引擎适配器。当玩家安装了 JEC 模组时，搜索栏自动使用 JEC 的 PinIn 引擎进行匹配，支持全拼、首字母、混合模式和模糊音。

### 可用性检查

```java
// 运行时检查 JEC 是否加载（客户端侧）
JecIntegration.isAvailable()
```

使用双重检查锁定 + `Class.forName("me.towdium.jecharacters.utils.Match")` 检测。

### 技术实现

JEC 通过 `jarJar` 内嵌 PinIn 库（`com.github.towdium:PinIn:1.6.0`），类在嵌套 JAR 内，编译期不可直接导入。因此使用 `MethodHandle` 反射调用：

```java
// 目标方法：me.towdium.jecharacters.utils.Match.contains(String, CharSequence)
MethodHandle containsHandle = MethodHandles.lookup().findStatic(
    matchClass, "contains",
    MethodType.methodType(boolean.class, String.class, CharSequence.class));
```

### 调用路径

```
PinyinMatcher.matches(displayName, query)
  ├─ JecIntegration.isAvailable() → true → JecIntegration.contains(displayName, query)
  └─ JecIntegration.isAvailable() → false → 内置 GB2312 拼音首字母匹配（回退）
```

### 依赖声明

```toml
# neoforge.mods.toml
[[dependencies.resourceobserver]]
modId="jecharacters"
type="optional"
side="CLIENT"
versionRange="[4.5.0,)"
```

```gradle
// build.gradle（CurseMaven）
compileOnly "curse.maven:just-enough-characters-250702:6681787"
localRuntime "curse.maven:just-enough-characters-250702:6681787"
```

### 内置回退：PinyinMatcher

**类路径：** `client.util.PinyinMatcher`

当 JEC 不可用时，使用内置的 GB2312 Level 1 拼音首字母匹配器：

- 基于 GB2312 二级汉字分区边界表（约 3755 个常用字）
- Unicode → GBK 字节 → 分区边界查找 → 拼音声母
- 支持三种匹配模式：直接包含、纯拼音首字母、混合匹配

## 添加新模组集成指南

1. 在 `integration/` 包创建 `XxxIntegration.java`
2. 实现 `isAvailable()` 静态方法（检查模组加载状态）
3. 实现数据探测方法（返回结构化结果记录）
4. 在 `BindingToolItem` 添加网络类型识别规则
5. 在 `ObserverBlockEntity.tick()` 添加采样分支
6. 必要时在 `ObserverDataPayload` 扩展数据字段
7. 更新 ViewModel 和 Mapper 以处理新数据
8. 更新 PageBuilder / Renderer 以展示新数据

参见：
- [[03-方块与实体]] — ObserverBlockEntity 采样逻辑
- [[04-物品系统]] — BindingToolItem 网络类型识别
- [[05-网络通信]] — Payload 数据结构
